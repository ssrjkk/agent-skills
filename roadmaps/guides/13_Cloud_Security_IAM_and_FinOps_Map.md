# Карта 13: Облачная Безопасность (IAM, OIDC, KMS), Supply Chain и FinOps

Современный продакшн строится по принципу **Zero Static Secrets** (отказ от долгоживущих ключей `AWS_ACCESS_KEY_ID` в переменных CI/CD и подах) и прозрачного контроля облачного чека (FinOps).

---

## 1. Бестокенная аутентификация: OIDC и Workload Identity

### Проблема старого подхода:
Хранение статических ключей облака в GitHub Secrets или GitLab Variables опасно: ключи забывают ротировать, их могут скомпрометировать через утечку логов пайплайна.

### Как работает OIDC (OpenID Connect) в CI/CD:
1. GitHub Actions / GitLab CI генерирует короткоживущий криптографически подписанный **JWT-токен** для конкретного запуска джобы (внутри зашиты `repo:org/backend-api:ref:refs/heads/main`).
2. Пайплайн отправляет этот JWT в облачный **STS (Security Token Service)** (`AssumeRoleWithWebIdentity`).
3. Облачный IAM проверяет подпись через OIDC-провайдер GitLab/GitHub, сверяет имя репозитория и ветку в Trust Policy и выдает **временные учетные данные на 15–60 минут**.

### Как поды в Kubernetes ходят в S3/SQS без паролей (IRSA / Pod Identity):
- К `ServiceAccount` микросервиса в K8s привязывается IAM-роль облака через аннотацию (`eks.amazonaws.com/role-arn` или Pod Identity Association).
- `kubelet` автоматически монтирует временный проекционный токен в под, и AWS/GCP SDK прозрачно обменивает его на временный доступ к конкретному S3-бакету.

## 2. Безопасность цепочки поставок (Supply Chain Security: SBOM & Cosign)

1. **Генерация SBOM (Software Bill of Materials):**
   - При каждой сборке образа утилита **Syft** или **Trivy** создает полный паспорт всех пакетов и библиотек внутри контейнера в формате CycloneDX / SPDX:
     ```bash
     trivy image --format cyclonedx --output sbom.json ghcr.io/org/backend-api:1.0.0
     ```
2. **Криптографическая подпись образов (Sigstore Cosign):**
   - Сразу после пуша в Container Registry образ подписывается в бесключевом режиме (Keyless signing через OIDC) с помощью **Cosign**:
     ```bash
     cosign sign --yes ghcr.io/org/backend-api@sha256:abcd...
     ```
3. **Проверка подписи при деплое в K8s:**
   - Политика **Kyverno (`verifyImages`)** на входе в кластер проверяет криптографическую подпись образа. Если злоумышленник подменил образ в регистри или попытался запустить неподписанный контейнер — Kubernetes заблокирует запуск пода.

## 3. Практический FinOps в Kubernetes (Как сократить счет за облако на 40–60%)

| Рычаг оптимизации | Инструмент | Как работает и сколько экономит |
| :--- | :--- | :--- |
| **Видимость затрат по неймспейсам** | **OpenCost** / Kubecost | Показывает в Grafana реальную стоимость каждого пода, неймспейса и команды разработчиков в долларах/рублях, выявляет «зомби-ресурсы» (Idle resources). |
| **Right-sizing (`requests`)** | **VPA** (режим `Off`) + **Goldilocks** | Разработчики часто прописывают `requests: cpu: 2000m`, когда сервис реально потребляет `50m`. Goldilocks анализирует реальные метрики и выдает точные рекомендации для снижения `requests`. |
| **Spot / Preemptible узлы** | **Karpenter** | Запуск всех stateless-воркеров и CI-раннеров на Spot-инстансах дает скидку **до 60–70%** по сравнению с On-Demand. При уведомлении об изъятии ноды за 2 минуты Karpenter плавно переносит поды. |
| **Автовыключение Dev/Stage стендов ночью** | **kube-green** / KEDA | Автоматический скейлинг всех деплойментов в `dev` и `staging` неймспейсах в `0` реплик с 20:00 до 08:00 и на выходные экономит **~65% стоимости** тестовых контуров. |
| **Очистка S3 и Container Registry** | S3 Lifecycle + Registry GC | Автоматическое удаление тегов образов из PR старше 14 дней и перевод старых бэкапов в `Glacier` / `Cold Storage`. |
