Промпт

# Golden Eval Set Before Any Prompting

Write the agent's golden eval set BEFORE tuning a single prompt. No eval set = no objective quality, only vibes.

When to use

  • Stage 1 of the AI conveyor, before writing the first prompt
  • Every time the agent's job changes scope

Prompt

You are an AI QA engineer. Build a golden eval set for the agent below:
- >= 20 cases across 5 categories: happy paths (8), edge inputs (4),
  refusal cases (4), adversarial/injection (2), regression anchors (2+)
- Each case: input, expected behaviour (observable, not vibes), severity
- 3 cases MUST be ones the current design will fail (they define the next work)
- A runner spec: how to execute the set and compute a pass rate
Output: the eval set as a table + the runner spec.
Agent job: <ONE SENTENCE + TOOLS>

Gate this satisfies

Stage 1 · gates 2-3: eval set written before prompting, refusal policy explicit.

# Золотой eval-набор до любого промптинга

Напишите золотой eval-набор агента ДО настройки хотя бы одного промпта. Нет eval-набора — нет объективного качества, только «на глаз».

Когда использовать

  • Этап 1 AI-конвейера, до первого промпта
  • Каждый раз, когда меняется скоуп задачи агента

Промпт

Ты — AI-инженер по качеству. Собери золотой eval-набор для агента ниже:
- >= 20 кейсов по 5 категориям: счастливые пути (8), краевые входы (4),
  кейсы отказа (4), атакующие/инъекции (2), якоря регрессий (2+)
- Каждый кейс: вход, ожидаемое поведение (наблюдаемое, не «на глаз»), критичность
- 3 кейса ОБЯЗАТЕЛЬНО должны провалиться текущей конструкцией (они задают следующую работу)
- Спецификация раннера: как исполнить набор и посчитать долю прохождений
Вывод: eval-набор таблицей + спецификация раннера.
Задача агента: <ОДНО ПРЕДЛОЖЕНИЕ + ИНСТРУМЕНТЫ>

Закрываемый гейт

# Guardrails, Refusal Enforcement, Cost Budget

Assume users will attack the agent and finance will audit its bill. Produce the safety-and-cost plan.

When to use

  • Stage 4 of the AI conveyor, when the agent MVP is public

Prompt

You are an AI platform engineer. Harden this agent:
1. Prompt-injection suite: >= 8 attack cases (indirect via tools, role-play, encoded payloads)
2. Refusal enforcement IN CODE: output schema with refusal field, post-check, retry policy
3. Cost/latency: per-request accounting, monthly budget, alert at 60% and 90%
4. Caching: what to cache (prefixes, RAG chunks), expected savings, eval pass-rate guard
5. Drift: same-input probe set, alarm on quality regression after model/provider updates
Output: ordered checklist with effort per item, plus the injection suite.
Agent: <PASTE THE LOOP AND STACK>

Gate this satisfies

Stage 4 · gates 1-4: injection suite passes, code-enforced refusals, cost/latency alerting, measured caching.

# Guardrails, принудительный отказ, бюджет стоимости

Считайте, что пользователи будут атаковать агента, а финансы будут проверять его счёт. Составьте план безопасности и стоимости.

Когда использовать

  • Этап 4 AI-конвейера, когда MVP агента публичен

Промпт

Ты — AI-платформенный инженер. Закали агента:
1. Набор prompt-инъекций: >= 8 атак (косвенные через инструменты, role-play, закодированные payload)
2. Принудительный отказ В КОДЕ: схема вывода с полем отказа, пост-проверка, политика повтора
3. Стоимость/латентность: учёт на каждый запрос, месячный бюджет, алерты на 60% и 90%
4. Кэширование: что кэшировать (префиксы, RAG-чанки), ожидаемая экономия, защита доли прохождения eval
5. Дрейф: набор проб «одинаковый вход», сигнализация регрессии качества после обновления модели/провайдера
Вывод: чек-лист по приоритету с трудозатратами на пункт, плюс набор инъекций.
Агент: <ЦИКЛ И СТЕК>
