Карта 03 (Расширенная): CI/CD, IaC и GitOps

1. Построение CI/CD пайплайнов (GitLab CI / GitHub Actions)

  • Архитектура и этапы пайплайна:
  • Стандартный флоу: Lint & Static Analysis -> Unit/Integration Tests -> Security Scans (SAST/Secrets) -> Build & Push Image -> CD Deployment.
  • Оптимизация времени выполнения: кэширование зависимостей (actions/cache, GitLab cache), параллельное выполнение матричных тестов (matrix strategy), условие запуска джоб по измененным путям (rules:changes / paths).
  • Переиспользование кода в CI: использование Composite Actions и Reusable Workflows в GitHub Actions, механизмов extends и include:project в GitLab CI.
  • Раннеры и безопасность сборки:
  • Развертывание собственных раннеров в Kubernetes (GitLab Runner Helm Chart, Actions Runner Controller — ARC).
  • Безопасная сборка образов без использования небезопасного Docker-in-Docker (DinD) с привилегированным режимом: применение Kaniko или BuildKit rootless.
  • Бестокенная аутентификация через OIDC (OpenID Connect) для безопасного доступа CI-пайплайна к облачным ресурсам (AWS IAM / Vault) без хранения статических ключей в переменных CI.

2. Infrastructure as Code (Terraform / OpenTofu)

  • Концепции и синтаксис:
  • Управление провайдерами, ресурсами (resource), источниками данных (data), входными переменными (variable), выходными данными (output) и локальными вычислениями (locals).
  • Управление потоком выполнения: аргументы count и for_each, динамические блоки (dynamic), использование встроенных функций (templatefile, jsonencode, merge).
  • Управление состоянием (State Management):
  • Настройка удаленного бэкенда (S3 совместимое хранилище) с поддержкой распределенных блокировок (DynamoDB / native S3 locks).
  • Манипуляции со стейтом: команды terraform state list, mv, rm, импорт существующих ресурсов через terraform import или блоки import {}.
  • Масштабирование конфигураций: разделение по директориям или использование Terragrunt для управления DRY-конфигурациями и зависимостями между модулями.
  • Модульность и валидация:
  • Проектирование универсальных версионируемых модулей инфраструктуры.
  • Проверка качества IaC-кода: terraform fmt, terraform validate, статический анализ через tflint, сканирование безопасности через Trivy config / Checkov.
  • Автоматизация IaC в Pull Request через инструменты вроде Atlantis (автоматический запуск terraform plan в комментарии к PR и применение после аппрува).

3. Управление конфигурацией (Ansible)

  • Организация репозитория: структура ролей, статический и динамический Inventory (например, интеграция с AWS EC2 API).
  • Обеспечение идемпотентности плейбуков, использование handlers для перезапуска сервисов только при изменении конфигурации.
  • Шаблонизация конфигурационных файлов с помощью Jinja2, управление переменными с учетом приоритетов (group_vars, host_vars).
  • Шифрование секретов в репозитории с помощью ansible-vault.
  • Тестирование ролей в изолированных контейнерах с помощью Molecule. Сборка готовых золотых образов ОС (Golden Images) с помощью Packer + Ansible.

4. GitOps (ArgoCD / Flux)

  • Принципы GitOps: декларативное описание всей инфраструктуры и приложений в Git, Pull-модель синхронизации кластера агентом вместо Push-деплоев из CI.
  • ArgoCD на практике:
  • Сущности Application и ApplicationSet для автоматического развертывания множества приложений на один или десятки кластеров по паттернам генераторов (Git directories, clusters).
  • Паттерн App of Apps (родительское приложение управляет списком всех дочерних сервисов).
  • Использование Sync Waves и Sync Hooks (например, запуск миграций базы данных в хуке PreSync до обновления основного деплоя приложения).
  • Прогрессивная доставка (Argo Rollouts): реализация стратегий Canary и Blue-Green деплоев с автоматическим откатом (Rollback) в случае роста метрик ошибок в Prometheus.
