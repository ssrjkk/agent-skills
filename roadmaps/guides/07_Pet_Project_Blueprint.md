# Практический план: Сквозной DevOps Пет-Проект (Production-Grade)

Данный проект охватывает все ключевые сферы современного DevOps и станет отличным дополнением к резюме.

## Архитектура проекта
- **Приложение:** Микросервисная архитектура (API-сервис на Go/Python + воркер фоновых задач).
- **Хранилища:** PostgreSQL (основная БД) + Redis (кэш/очередь).
- **Инфраструктура:** Облачный кластер Kubernetes (или локальный Minikube/Kind для тестов) + S3-совместимое хранилище для бэкапов.

---

## Пошаговый план реализации

### Шаг 1. Контейнеризация
- [ ] Написать оптимизированный multi-stage `Dockerfile` для каждого сервиса (финальный размер образа менее 40 МБ, работа под непривилегированным пользователем `nonroot`).
- [ ] Сформировать `docker-compose.yml` с настроенными `healthcheck` для базы данных и кэша, чтобы сервисы стартовали только после полной готовности зависимостей.

### Шаг 2. Infrastructure as Code (Terraform)
- [ ] Описать в **Terraform** создание VPC, подсетей, сетевых экранов, S3-бакета для бэкапов и кластера Kubernetes.
- [ ] Организовать код в виде переиспользуемых модулей. Настроить удаленный бэкенд стейта в S3.

### Шаг 3. CI/CD пайплайн (GitHub Actions / GitLab CI)
- [ ] Реализовать пайплайн:
  1. Линтинг кода и проверка `Dockerfile` (Hadolint).
  2. Запуск unit-тестов.
  3. Сканирование репозитория на утечки секретов (`Gitleaks`).
  4. Сборка Docker-образа, сканирование его на критические уязвимости через **Trivy** (с падением пайплайна при наличии CRITICAL уязвимостей).
  5. Пуш образа в Container Registry с тегом по SHA коммита.
  6. Автоматическое обновление версии тега в GitOps-репозитории.

### Шаг 4. Деплой через GitOps (ArgoCD + Helm)
- [ ] Создать собственный **Helm-чарт** для приложения:
  - `Deployment` с настроенными `securityContext` (readOnlyRootFilesystem, drop ALL capabilities), probe-ами (`startup`, `readiness`, `liveness`) и ограничениями ресурсов (`requests`/`limits`).
  - `Service` и `HTTPRoute` (Gateway API) с автоматическим выпуском сертификатов через `cert-manager`.
  - `HorizontalPodAutoscaler` (HPA) и `PodDisruptionBudget` (PDB).
- [ ] Установить **ArgoCD** и настроить синхронизацию приложения по паттерну App of Apps.

### Шаг 5. Наблюдаемость (Observability)
- [ ] Развернуть стек `kube-prometheus-stack` и `Grafana Loki`.
- [ ] Сконфигурировать дашборды в Grafana по методу RED (RPS, частота ошибок, задержки).
- [ ] Настроить Alertmanager для отправки критических алертов в Telegram/Slack чат.

### Шаг 6. Оформление портфолио
- [ ] Подготовить красивый `README.md` с архитектурной схемой, инструкцией по развертыванию и скриншотами успешного пайплайна, дашбордов Grafana и дерева ArgoCD.
