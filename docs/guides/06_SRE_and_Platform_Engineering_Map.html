Карта 06 (Расширенная): SRE, Highload и Platform Engineering

1. Практики Site Reliability Engineering (SRE)

  • Управление надежностью:
  • Разделение понятий SLI (метрика качества: например, доля успешных запросов быстрее 200мс), SLO (целевой показатель: 99.9% за скользящий месяц) и SLA (бизнес-контракт с финансовыми штрафами за нарушение).
  • Error Budget (Бюджет ошибок): концепция баланса между скоростью выпуска новых фич и стабильностью системы. Настройка Multi-window, Multi-burn-rate алертов по скорости сжигания бюджета.
  • Культура инцидентов и устойчивость:
  • Организация дежурств (On-call rotations), написание исчерпывающих Runbooks и Playbooks.
  • Проведение Blameless Postmortems (разбор полетов без поиска виновных, выявление корневых причин методом «5 почему» и постановка Action Items для предотвращения рецидивов).
  • Chaos Engineering: внедрение сбоев в тестовые и продакшн-окружения (Chaos Mesh, LitmusChaos) для проверки реакции системы на падение нод или сетевые задержки.

2. Platform Engineering и Self-Service IDP

  • Переход от ручной обработки тикетов силами DevOps к созданию внутренних платформ самообслуживания (Internal Developer Platforms).
  • Crossplane: декларативное управление облачной инфраструктурой (БД, бакеты, очереди) прямо из манифестов Kubernetes с помощью концепций XRD (Composite Resource Definitions) и Composition, позволяющих разработчикам заказывать ресурсы через YAML-манифест.
  • Backstage: создание единого портала разработчика (каталог микросервисов, шаблоны создания новых проектов с преднастроенным CI/CD и мониторингом по принципу Golden Paths).

3. Эксплуатация Stateful-систем (Highload DB & Queues)

  • PostgreSQL в продакшене:
  • Высокая доступность и автомастер-фейловер: Patroni или оператор CloudNativePG.
  • Пулинг соединений: PgBouncer (режимы session, transaction, statement pooling) для защиты базы от исчерпания памяти при скачках трафика.
  • Резервное копирование и PITR (Point-in-Time Recovery) с помощью WAL-G или pgBackRest с обязательным регулярным тестированием восстановления.
  • Тюнинг и диагностика: анализ медленных запросов (pg_stat_statements, EXPLAIN (ANALYZE, BUFFERS)), настройка параметров памяти (shared_buffers, work_mem, effective_cache_size) и параметров autovacuum.
  • Кэширование и Очереди сообщений:
  • Redis / Valkey: стратегия репликации, персистентность (RDB vs AOF), обеспечение высокой доступности через Redis Sentinel и масштабирование через Redis Cluster.
  • Apache Kafka: устройство топиков, партиций, факторов репликации (ISR), управление consumer groups, мониторинг Consumer Lag, эксплуатация в Kubernetes через оператор Strimzi.
  • RabbitMQ: типы обмена (Exchanges), кворумные очереди (Quorum Queues), настройка Dead Letter Exchanges (DLX) для обработки упавших сообщений.

4. FinOps (Оптимизация затрат)

  • Мониторинг утилизации ресурсов в Kubernetes через Kubecost или OpenCost.
  • Использование Spot / Preemptible инстансов для снижения стоимости вычислений.
  • Right-sizing процессорных и оперативных ресурсов подов на основе исторических данных (VPA в режиме рекомендаций).
