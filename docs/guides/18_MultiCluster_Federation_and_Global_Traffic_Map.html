Карта 18: Мульти-Кластерная Архитектура (Cluster API, Cilium Cluster Mesh, vCluster)

В крупных компаниях никогда не ограничиваются одним гигантским кластером Kubernetes («единая точка отказа», лимиты etcd и радиус поражения при обновлении). В 2026–2027 годах стандартом стало управление флотом кластеров.

1. Почему несколько кластеров лучше одного монолита?

  • Ограничение Blast Radius (Радиуса поражения): неудачное обновление CNI-плагина или CRD в одном кластере не положит весь бизнес.
  • Гео-распределение (Multi-Region): кластеры в Москве/СПб, Франкфурте и Сингапуре для минимального RTT до пользователей и соблюдения законов о локализации данных.
  • Жесткая изоляция контуров: физическое разделение prod, staging и pci-dss окружений.

2. Инструменты управления флотом кластеров

Cluster API (CAPI) — Kubernetes управляет Kubernetes

  • Вместо того чтобы раскатывать каждый кластер отдельным пайплайном Terraform, поднимается один Management Cluster, в который устанавливается Cluster API.
  • Создание нового рабочего кластера в AWS, Yandex Cloud или на Bare-Metal (через провайдеры CAPA, CAPV, Metal3) сводится к применению YAML-манифеста kind: Cluster и kind: MachineDeployment (точно так же, как Deployment управляет подами, MachineDeployment управляет виртуальными или физическими серверами).

vCluster (Виртуальные кластеры внутри одного физического)

  • Проблема: выдавать каждому разработчику или на каждый Pull Request отдельный полноценный EKS/K8s кластер — долго (15 минут) и безумно дорого.
  • Решение (vCluster): поднимает легковесный виртуальный Control Plane (k3s / k8s-apiserver) внутри обычного неймспейса хост-кластера за 5 секунд.
  • Разработчик получает полные права cluster-admin внутри своего vCluster, может ставить свои CRD и операторы, но рабочие поды планируются на общих физических узлах хост-кластера (экономия до 80% ресурсов на тестовых средах).

3. Межкластерная сеть и Глобальная балансировка (GSLB)

  • Cilium Cluster Mesh:
  • Объединяет несколько кластеров Kubernetes в единое плоское сетевое пространство поверх туннелей или маршрутизируемой сети (без NAT).
  • Позволяет сервису в Cluster-A прозрачно обращаться к базе данных или сервису в Cluster-B через глобальные сервисы (io.cilium/global-service: "true") с автоматическим фейловером между дата-центрами.
  • ExternalDNS + GSLB (k8gb / Route53 / Cloudflare):
  • Контроллер ExternalDNS следит за объектами Gateway / HTTPRoute и Service в кластере и автоматически создает/удаляет DNS-записи у провайдера.
  • k8gb (Kubernetes Global Balancer): открытый GSLB-балансировщик, который проверяет здоровье эндпоинтов в разных кластерах и отдает клиентам DNS-ответы только тех дата-центров, где поды живы.
