# Карта 02 (Расширенная): Программирование и Контейнеризация

## 1. Автоматизация на Python и Go
- [ ] **Python для инфраструктуры:**
  - Управление виртуальными окружениями и зависимостями с помощью современных инструментов (`uv`, `poetry`).
  - Написание надежных скриптов автоматизации с использованием библиотек:
    - `requests` / `httpx` (взаимодействие с внешними REST API с обработкой таймаутов и ретраев).
    - `PyYAML`, `toml` (парсинг конфигурационных файлов).
    - `Jinja2` (генерация конфигов и шаблонов манифестов по динамическим данным).
    - `boto3` (программирование в AWS: управление S3 бакетами, EC2 инстансами, IAM).
    - `kubernetes` (официальный Python-клиент для работы с API K8s).
  - Тестирование кода автоматизации через `pytest` и статический анализ через `ruff` и `mypy`.
- [ ] **Go (Golang) для DevOps и Cloud-Native:**
  - Понимание базовых конструкций языка: структуры, интерфейсы, указатели, обработка ошибок.
  - Конкурентность: горутины (`go func()`), каналы (`chan`), паттерны синхронизации (`sync.WaitGroup`, `sync.Mutex`), работа с контекстом (`context.Context` для таймаутов и отмены операций).
  - Сборка бинарников с флагами оптимизации (`CGO_ENABLED=0 go build -ldflags="-w -s"`).
  - Создание CLI-утилит с помощью библиотеки `Cobra`. Чтение исходного кода инфраструктурных инструментов (Terraform провайдеров, утилит управления кластером).

## 2. Глубокое устройство контейнеров
- [ ] **Архитектура рантаймов:**
  - Различие между монолитным Docker Daemon, стандартом OCI (Open Container Initiative), низкоуровневыми рантаймами (`runc`, `crun`) и высокоуровневыми рантаймами (`containerd`, `CRI-O`).
- [ ] **Файловая система OverlayFS:**
  - Принцип работы слоев: `lowerdir` (базовые неизменяемые слои образов), `upperdir` (слой изменений контейнера), `merged` (объединенное представление для запущенного контейнера) и механизм Copy-on-Write (CoW).
- [ ] **Best Practices написания Dockerfile:**
  - **Multi-stage builds:** изоляция среды сборки (компиляторы, исходный код, SDK) от финального продакшн-образа.
  - Использование минимальных базовых образов: `alpine` (с пакетным менеджером apk), Google `distroless` (содержащих только рантайм и зависимости без оболочки и шелла) или `scratch` (для скомпилированных статически бинарников на Go/Rust).
  - Оптимизация кэширования слоев: правильная последовательность инструкций (`COPY go.mod` -> `RUN go mod download` -> `COPY . .`).
  - Безопасность сборки: запуск процессов от непривилегированного пользователя (`USER nonroot`), использование `.dockerignore` для исключения лишних файлов, передача секретов в процессе сборки через `RUN --mount=type=secret` (без сохранения в истории слоев).
  - Использование **BuildKit** и `docker buildx` для сборки мультиархитектурных образов (`linux/amd64` и `linux/arm64`).
- [ ] **Сети и тома в контейнерах:**
  - Типы сетевых драйверов Docker: `bridge` (изолированная сеть с NAT), `host` (использование сетевого стека хоста), `overlay` (межхостовая сеть для Swarm/K8s).
  - Управление данными: `Volumes` (управляемые Docker области на хосте), `Bind Mounts` (монтирование произвольных директорий хоста), `tmpfs` (хранение данных в оперативной памяти).
- [ ] **Docker Compose:**
  - Организация локальной среды разработки, использование секций `healthcheck` и `depends_on: condition: service_healthy` для синхронизации старта зависимых сервисов (например, ожидания готовности PostgreSQL перед запуском веб-приложения).
  - Управление конфигурацией через `.env` файлы и разделение окружений через профили (`profiles`).
